# План отладки URDT: реальные UI-прогоны

Дата старта: 2026-07-12

## Цель и границы

Цель: довести URDT до самостоятельной работы ИИ с UI запущенного Unity-приложения.

- Исходные восемь прогонов фиксированы и не изменяются.
- Любое исправление допускается только в URDT, не в `Assets/URDT_TestPoligon` и не в тестовом сценарии.
- Взаимодействие с UI выполняется только реальным вводом через URDT: указатель, нажатия, клавиатура, прокрутка и ожидание. Нельзя вызывать обработчики UI, менять поля компонентов или подменять результат.
- Источники истины: `query`, `inspect`, снимок `UrdtTestPoligonDebugTarget`, ответ команды, `wait_for` и структурированные логи. Скриншоты не используются для принятия результата.
- Unity Editor проверяется через Unity Skills на `http://127.0.0.1:8090`; URDT-транспорт обнаруживается через его живой endpoint/handshake, без предположения порта.

## Роли и независимая проверка

- Оркестратор: строит тест, исполняет только реальные действия и ведет отчёт.
- Анализатор, GPT-5.5 medium: независимо читает текущее состояние/дельты и сообщает факты.
- Судья, GPT-5.5 medium: независимо проверяет критерии приемки и отсутствие ложноположительного результата.
- Воркер, GPT-5.5 low: выполняет ограниченные технические подзадачи без подмены UI-результата.
- Итог подтверждается машинными проверками Unity/компиляции и независимым судьей; исполнитель не объявляет результат единственным валидатором.

## Общий цикл каждого теста

1. Снять состояние сцены, Editor Play Mode, доступность URDT, цели и их debug-state.
2. Определить только по debug-state доступный реальный input и координаты/целевой объект.
3. Выполнить один шаг прогона.
4. Снять дельту: ответ URDT, состояние цели, структурированные события и ожидаемое изменение.
5. При успехе перейти к следующему шагу. При неуспехе локализовать слой (discovery, transport, input, ожидание, наблюдаемость), исправить только URDT, скомпилировать и повторить тот же неизменный тест. Не более пяти попыток на тест.
6. После пятой неудачи зафиксировать в `URDT_UI_Debug_Report.md` попытки, доказательства и нерешенную проблему; перейти к следующему тесту.

## Набор неизменяемых прогонов

1. Открыть и закрыть модальное окно.
2. Ввести в поле `привет Мир`, изменить на `приМир`, очистить; между требуемыми действиями выдержать одну секунду.
3. Включить toggle и через секунду выключить.
4. Установить slider последовательно: `0.5`, `0.3`, `1.0`, `0.0`.
5. Выбрать в combo box последовательно: `C`, `A`, `B`.
6. Нажать primary button один раз, ожидание одна секунда, затем double click.
7. Прокрутить scroll от начала к середине, ожидание, от середины к концу, ожидание, от конца к началу.
8. Выполнить в одном сеансе все предыдущие семь прогонов в их заданном порядке.

## Очередность и критерии

Порядок строго: 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> 8. Для каждого действия успешность требует одновременно: успешный протокольный ответ, наблюдаемую дельту соответствующей debug-цели и отсутствие нового ошибки URDT в структурированных логах. Таймауты равны одной секунде там, где они заданы прогоном; это проверяется по временным меткам/событиям, а не искусственной установкой состояния.

## Журналирование и токены

В отчёте для каждого теста фиксируются: стартовое состояние, все шаги и дельты, номер попытки, диагностированный слой, исправления только в URDT, итог и оценка токенов по трем категориям: операция, анализ, исправление. Значения токенов являются оценкой, поскольку инструменты не возвращают раздельный точный счетчик.
