# Bitrix Task Field Contract

> Источник правды: [HowToDecomposeTask_ForAI.md → Этап 2](../../../../../kbpro-wiki/raw/Architecture/CoreFramework/Guides/HowToDecomposeTask_ForAI.md) и [GEMINI.md](../../../../../llm-wiki/raw/ide-rules/GEMINI.md).

## Структура файла

Файл — это **JSON-массив** объектов задач. Каждый элемент:

```json
{
  "fields": {
    "TITLE": "...",
    "DESCRIPTION": "...",
    "TAGS": ["..."],
    "GROUP_ID": 100,
    "RESPONSIBLE_ID": 66,
    "PRIORITY": 3,
    "ALLOW_TIME_TRACKING": "1",
    "UF_TASKS_TASK_1783529349965": 8,
    "DURATION_TYPE": "hours",
    "DURATION_PLAN": 8
  }
}
```

## Поля

| Поле | Тип | Правило |
|------|-----|---------|
| `TITLE` | string | Строго `[Dev][<функционал>] <Модуль> - <Шаг>` (см. «Правило именования» ниже). Это шаг, а не модуль целиком. |
| `DESCRIPTION` | string | Полная самостоятельная карточка из 4 частей (цель с ожидаемым результатом и применимыми требованиями → `📄 Раздел ГДД:` deep-link → `Что сделать` → `Готово, когда` + картинки по провенансу), НЕ дословный дамп. Состав задаёт выбранный паттерн; сборка — в `description-blocks.md`. |
| `TAGS` | string[] | Только здесь. Обязательны: `Dev`, версия (напр. `v1.0.x`), приоритет (`p1`–`p5`), блок (напр. `логика`, `арт`). |
| `GROUP_ID` | int | Целевой Bitrix project/workgroup. Для «Ну Погоди! Роботы» используется `100`; `94` — старый пример. Не менять проект молча. |
| `RESPONSIBLE_ID` | int | Всегда `66`. |
| `PRIORITY` | int | `1` низкий / `2` средний / `3` высокий. Логика = 3, Визуал = 2, остальное = 1. |
| `ALLOW_TIME_TRACKING` | string | Всегда `"1"`. |
| `UF_TASKS_TASK_1783529349965` (или `UF_TASK_CAPACITY`) | int | Оценка сложности в человеко-часах. Обязательное целое число: `1`, `4`, `8`, `20`, `77`. Если источник задан в человеко-днях, конвертировать один раз: `ceil(ч-д * 8)`. В JSON писать в системное поле `UF_TASKS_TASK_1783529349965`. |

## Правило планирования Ганта по человеко-часам

- Перед созданием или переназначением задач нужно учитывать `UF_TASK_CAPACITY` (в часах).
- Рабочее окно планирования: `10:00–18:00 МСК`, ровно `8` рабочих часов в день.
- На один рабочий день одного исполнителя можно поставить суммарно не более `8` человеко-часов.
- В JSON задавать `DURATION_TYPE="hours"` и `DURATION_PLAN` равным оценке в человеко-часах. При API-записи также синхронизировать системное поле `UF_TASKS_TASK_1783529349965` с тем же числом.
- Для видимых стрелок в Ганте у следующей задачи нужно записать `DEPENDS_ON=[previousTaskId]`.

## Правило именования TITLE (обязательно)

Формат строго: `[Dev][<функционал>] <Имя модуля> - <Название шага>`.

- `[Dev]` — постоянный префикс.
- `[<функционал>]` — второй блок в скобках, тип функционала шага. Допустимо: `логика` · `графика` · `анимации` · `эффекты` · `звуки` · `озвучка` · `туторы`.
- `<Имя модуля>` — модуль/эпик; `<Название шага>` — конкретный шаг из ТЗ.
- Значение `[<функционал>]` должно совпадать с тегом блока в `TAGS`.

Примеры: `[Dev][логика] Кариес - Этап 1 «Анестезия»`, `[Dev][графика] Диагностика - ассеты модуля`, `[Dev][озвучка] Таймер - реплики окна блокировки`.

## Кодировка

Файл сохраняется как **UTF-8 с BOM** (кириллица должна корректно отображаться в Windows / Unity / Obsidian / Bitrix). Это общий конвеншен проекта (см. AGENTS.md / LLM-WIKI.md).

## Запреты

- ❌ Теги текстом в `DESCRIPTION`.
- ❌ Одна задача = целый модуль.
- ❌ Дословный дамп ГДД, ссылка вместо полной цели или одинаковый текст в 7 функционалах.
- ❌ Филлеры («реализовать согласно ТЗ», «сделать качественно»); ❌ пустой/неизмеримый DoD.
- ❌ Картинка не из раздела шага / не того функционала / дубль / «по смыслу».

## Обязательно

- ✅ Ровно один `📄 Раздел ГДД:` deep-link на раздел шага, с автопроскролом: `…/edit?tab=t.<TAB_ID>#heading=h.xxx` (`?tab=` обязателен, иначе не проскроллит).
- ✅ Измеримый `Готово, когда` (DoD).
- ✅ Картинки — строго по манифесту/провенансу (см. паттерн §6).

## Примечание про теги при импорте

Поле `TAGS` физически проставляется импортёром **вторым** API-вызовом (`task.item.update`), а не в `tasks.task.add`. Для сборщика JSON это прозрачно — просто всегда клади теги в `TAGS`. Детали — в скилле `bitrix-task-importer`.
