# Структура поля DESCRIPTION (карточка задачи)

> Источник правды по составу и принципам — **выбранный паттерн** из [`task-patterns/`](../task-patterns/) (для дева — [dev-task-pattern.md](../task-patterns/dev-task-pattern.md) §5–§6, §8). Этот файл описывает, как карточка **собирается в строку `DESCRIPTION`** для Bitrix.

`DESCRIPTION` — это **полная карточка из 4 частей**, а НЕ дословный дамп ГДД. Полный текст ГДД остаётся в документе и достаётся по deep-link; в задаче формулируется весь необходимый для конкретного функционала контракт результата.

## Части карточки

1. **Заголовок** — идёт в поле `TITLE`, не в `DESCRIPTION`. Формат `[Dev][<функционал>] <Модуль> — <Шаг>`.
2. **Цель** — полное самостоятельное описание того, что сдаёт ЭТОТ специалист по ЭТОМУ шагу: ожидаемый результат, применимые требования и границы задачи. Если есть зависимость — **первой строкой** `Зависит от: <TITLE предыдущего шага>`. Для `🔁`-дубля — строка `Дубль механики …, переиспользовать`.
3. **Ссылка на раздел ГДД** — `📄 Раздел ГДД: <deep-link>` с автопроскролом к заголовку: `https://docs.google.com/document/d/<DOC_ID>/edit?tab=t.<TAB_ID>#heading=h.<HEADING_ID>` (`heading_id` + `tab_id` — из индекса заголовков, построенного через Docs API). `?tab=t.<TAB_ID>` обязателен, иначе якорь не проскроллит; одновкладочный док — `tab=t.0`.
4. **Доп. описание:**
   - `Что сделать:` — 2–6 пунктов, **императив-результат**, строго по функциональной линзе (§4 паттерна). Не факты («есть прогресс-бар»), а действия («реализовать шкалу 0→100% с событием завершения»).
   - `Готово, когда:` — измеримый DoD (проверяемые критерии).
   - **Картинки** — только из этого раздела/функционала по манифесту (§6 паттерна): встречена в логике → в задачу `логика`, в анимациях → в `анимации`. Ровно в одну задачу, без дублей и лишних.

## Сборка в строку `DESCRIPTION`

Части 2–4 склеиваются переводами строк. В JSON — `\n` внутри строки:

```
"<полная цель и ожидаемый результат>\n\n📄 Раздел ГДД: <deep-link>\n\nЧто сделать:\n• …\n• …\n\nГотово, когда:\n• …\n• …"
```

- **Оценка достаточности 7–10 считается по частям 2 + 4 БЕЗ ссылки** — карточка обязана сама доводить разработчика до результата (§8 паттерна).
- **Разные функционалы → разные тексты.** 7 функционалов одного шага НЕ должны иметь одинаковый `DESCRIPTION`.
- **Достаточность важнее краткости:** формулируйте ёмко, но не опускайте требования, без которых нельзя реализовать или принять результат. Если пунктов `Что сделать` больше шести, сгруппируйте их логически, не теряя сути.
- Способ физической вставки картинок в Bitrix (вложение-файл vs `[IMG]`/URL в описании) уточняется через `b24-dev-mcp` на реализации.

## Сборка через генератор

Для Google-Doc источника генератор резолвит `DOC_ID`, экспортирует HTML во временный файл, строит **индекс якорей** и **манифест картинок**, затем на каждый шаг собирает карточку по каждому функционалу (deep-link из индекса, картинки из манифеста по провенансу), экранирует, пишет UTF-8+BOM. Самопроверка: parse, число задач, каждый deep-link резолвится в реальный `h.xxx`, 7 описаний шага не идентичны, картинки не дублируются/не из чужого раздела, нет филлеров. Генератор — вне `Assets/`, удалить после.

## Запреты

- ❌ Дословный дамп ГДД, ссылка вместо описания цели или неполная цель, которая вынуждает исполнителя искать критичные требования в документе.
- ❌ Один и тот же текст в 7 функционалах.
- ❌ Филлеры: «реализовать согласно ТЗ», «сделать качественно», «см. документ».
- ❌ Пустой/неизмеримый DoD.
- ❌ Картинка не из раздела шага / не того функционала / дубль / «по смыслу».
- ❌ Теги текстом в `DESCRIPTION` (только поле `TAGS`).

## Пример (значение поля DESCRIPTION)

```
Реализовать игровую логику ввода анестезии и разблокировку следующего этапа.

📄 Раздел ГДД: https://docs.google.com/document/d/1gly…p9fk/edit?tab=t.0#heading=h.anesthesia

Что сделать:
• Drag шприца к хит-зоне десны.
• Удержание N сек → шкала обезболивания 0→100%.
• По 100% — событие AnesthesiaDone, разблокировка бормашины.

Готово, когда:
• Отпускание до 100% сбрасывает прогресс.
• Повторный вход в шаг после Done невозможен.
```
