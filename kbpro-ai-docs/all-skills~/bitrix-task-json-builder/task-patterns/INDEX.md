# Индекс паттернов формирования задач

Реестр паттернов, по которым из исходных документов (ГДД/ТЗ) формируются задачи для разных отделов. **Каждый тип задач формируется по-своему** — у отделов разная гранулярность, состав карточки, поля трекера и работа с медиа. Скиллы-сборщики задач обязаны выбирать паттерн по типу задачи из таблицы ниже и следовать ему.

## Как пользоваться

1. Определи тип задачи / отдел (что именно заводим: дев-задачу, арт-задачу, задачу аниматору, задачу на написание/декомпозицию ГДД).
2. Открой соответствующий файл паттерна и следуй ему: исходный документ → принципы формирования → состав карточки → картинки → контракт полей → оценка.
3. Если паттерн ещё не реализован (статус «Планируется») — не выдумывай правила: подними вопрос с пользователем и заведи паттерн отдельно.

## Реестр

| Паттерн | Тип задач / отдел | Что покрывает | Статус | Файл |
|---|---|---|---|---|
| **Дев** | Разработка по шагам ГДД: `логика · графика · анимации · эффекты · звуки · озвучка · туторы` | Декомпозиция раздела ГДД 1:1 в дев-задачи, 4-частная карточка (заголовок / полная цель / deep-link на раздел / доп. описание + картинки), провенанс картинок, оценка ≥7 с циклом доработки | ✅ Готов | [dev-task-pattern.md](dev-task-pattern.md) |
| **Арт** | Создание арт-ассетов (арт-отдел) | Формирование задач на арт: списки ассетов, референсы, бренд-бук, форматы сдачи — **своя** гранулярность и состав карточки | 🕓 Планируется | `art-task-pattern.md` (TBD) |
| **Анимация** | Задачи аниматорам | Формирование задач на анимацию: Spine/Unity, тайминги, состояния, триггеры — **свой** паттерн | 🕓 Планируется | `animation-task-pattern.md` (TBD) |
| **ГДД** | Написание/декомпозиция ГДД | Формирование задач на подготовку и разбор дизайн-документа | 🕓 Планируется | `gdd-task-pattern.md` (TBD; см. также скилл `davasko-gdd-parser`) |

## Общие инварианты (действуют во всех паттернах)

- **Источник правды — исходный документ.** В задачу он попадает ссылкой на конкретный раздел (deep-link с автопроскролом), а не слепой копией.
- **Описание = контракт результата**, а не пересказ документа. Никакой воды и дублей.
- **Медиа — строго по провенансу:** картинка попадает в задачу только из своего раздела/типа, ровно в одну задачу, без лишних и без дублей.
- **Оценка перед заведением:** независимый изолированный судья-субагент проверяет задачу; порог и рубрика — в паттерне. Самовалидация запрещена (та же семья моделей допустима, если это отдельный субагент).
- **Экономия токенов:** детерминированные проверки — скриптом (0 токенов); LLM-судья — дёшево, батчами, без исходного документа в контексте.

## Добавление нового паттерна

1. Создай файл `<отдел>-task-pattern.md` в этой папке по структуре dev-паттерна: `Назначение · Исходный документ · Принципы формирования · Линза · Состав карточки · Медиа/провенанс · Контракт полей · Оценка · Экономия токенов · Анти-паттерны`.
2. Добавь строку в реестр выше (тип, что покрывает, статус, ссылка).
3. Пропиши в соответствующем скилле-сборщике, что для этого типа задач используется данный паттерн.
