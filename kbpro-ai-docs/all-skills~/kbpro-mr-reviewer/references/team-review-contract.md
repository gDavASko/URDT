# Контракт командного ревью MR

## Вход

Главный агент передает участникам только необходимые данные: base/head SHA или локальный
diff, описание MR, список измененных файлов, применимые правила и разрешенные read-only
команды. Внешняя публикация, изменение кода, коммит и работа с токенами не входят в
полномочия ревью.

## Передачи между ролями

`researcher` возвращает черновые findings с `file_path`, `line_number`, фрагментом
diff/кода, правилом, риском и предложением. `judge` проверяет каждый finding по
первичным артефактам, удаляет дубликаты и ложные срабатывания, затем отмечает
подтвержденные findings. `worker` преобразует только подтвержденный список в требуемый
формат. Главный агент сохраняет сведения о проверках и ограничениях.

## Решение

`PASS` возможен только после независимого judge и при отсутствии подтвержденных
замечаний. `CHANGES_REQUIRED` означает минимум одно подтвержденное замечание. `BLOCKED`
означает отсутствие diff, нужного контекста, независимого judge или обязательного
доказательства. Нельзя подменять `BLOCKED` выводом researcher.

## Внешние действия

Наличие `GITLAB_TOKEN`, URL MR или учетных данных не является разрешением на публикацию.
Перед любым внешним комментарием главный агент обязан показать preview и получить явное
разрешение пользователя.
