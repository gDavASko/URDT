# Свод правил: Проверка префабов, сцен и целостности ресурсов

Этот документ регламентирует правила инспекции префабов, сцен, ScriptableObject и ссылок на ассеты в проектах KBPro.

---

## 1. Проверка битых скриптов и компонентов (Missing Scripts)

* **Missing Script [Blocker]**: Полный запрет на коммиты с префабами (`.prefab`), сценами (`.unity`) или ScriptableObject (`.asset`), содержащими компоненты с битыми ссылками на C# скрипты. В текстовом формате сериализации YAML Unity такие проблемы можно выявить по следующим признакам:
  - **MonoBehaviour с fileID 0**: Поиск строки `m_Script: {fileID: 0}` внутри блоков компонентов типа `MonoBehaviour` (указывает на то, что скрипт отвязан).
  - **Несуществующий GUID скрипта**: Наличие ссылки `m_Script: {fileID: 11500000, guid: <32-значный_хэш>, type: 3}`, где указанный `<guid>` отсутствует во всех метафайлах проекта (`.meta`). Для проверки ИИ-агент должен выполнить поиск по проекту (`grep_search`) данного GUID. Если файл `.meta` с таким GUID не найден, скрипт удален или переименован без сохранения связей — это блокер.
  - **Предупреждения парсера**: Наличие записей `!u!114` (класс MonoBehaviour) без связанной структуры полей.
  Такие префабы вызывают утечки памяти, предупреждения в консоли и ошибки сборки проекта.

* **Missing References [Blocker]**: Сериализованные поля компонентов не должны содержать ссылок типа "Missing" на удаленные или измененные ресурсы. В YAML-файлах это проверяется так:
  - Наличие ссылок на ассеты с конкретным GUID (например, `m_Sprite: {fileID: 21300000, guid: <хэш>, type: 3}` или `m_AudioClip: {fileID: 8300000, guid: <хэш>, type: 3}`), где указанный `guid` не существует в репозитории (нет соответствующего `.meta` файла).
  - Для обязательных полей (например, кнопок, текстовых полей, скриптов логики) ссылки не должны сбрасываться в пустое состояние: `{fileID: 0}`.
  - В префабах и сценах не должно быть сломанных модификаций префабов: строки типа `m_CorrespondingSourceObject: {fileID: 0}` при наличии активных переопределений свойств.

## 2. Использование ComponentAccessor

* **ComponentAccessor во View**:
  - Для быстрого доступа к дочерним визуальным элементам (TMP Text, Image, Spine Skeleton) внутри сложных префабов представлений (View) должен быть настроен `ComponentAccessor`.
  - Запрещается осуществлять поиск этих элементов через `GetComponentInChildren` или `transform.Find` в рантайме. Ссылки должны быть привязаны через инспектор в соответствующие слоты `ComponentAccessor` на этапе сборки префаба.

## 3. Дубликаты и организация ресурсов

* **Отсутствие дубликатов ресурсов**:
  - Запрещается дублировать меши, звуковые файлы, текстуры или анимации в разных папках проекта. Если ресурс используется в нескольких модулях, он должен быть вынесен в общую папку ресурсов.
* **Настройки ассетов и метафайлов (`.meta`)**:
  - Каждому добавленному файлу ресурса (текстура, звук, скрипт) должен соответствовать `.meta` файл. Коммиты с новыми ассетами без их соответствующих `.meta` файлов запрещены, так как это ломает связи в Unity на других машинах разработчиков.
