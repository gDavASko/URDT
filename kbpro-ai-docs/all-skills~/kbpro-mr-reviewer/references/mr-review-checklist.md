# Сводный чек-лист рецензирования кода (Code Review Checklist) для KBPro

Этот чек-лист объединяет требования к стилю кода, архитектурным границам, принципам SOLID и рантайм-оптимизациям платформы KBPro.

---

## 1. Кодировка, Форматирование и Структура файлов

* **Кодировка и русские символы**: Все файлы кода C# (`.cs`), конфигураций и логов должны быть сохранены в UTF-8 с BOM. ИИ-агент должен обращать особое внимание на корректность отображения кириллицы (комментарии, строки) — недопустимы битые символы (кракозябры) в коде или логах.
* **Один класс на файл**: Имя файла должно полностью совпадать с именем объявленного в нем класса или интерфейса.
* **Форматирование скобок (Allman)**: Открывающая фигурная скобка `{` пишется на новой строке с тем же отступом. Отступы должны быть выполнены пробелами (4 пробела), использование символов табуляции запрещено.
* **Модификаторы доступа**: Все члены класса (классы, методы, свойства, поля) должны иметь явно прописанные модификаторы доступа (например, `private int _value;` вместо `int _value;`).
* **Порядок членов класса**:
  1. Константы (`const`)
  2. Статические поля (`static readonly` / `static`)
  3. Сериализуемые приватные поля (`[SerializeField] private`)
  4. Приватные обычные поля (`private`)
  5. Свойства (`public` / `private` properties)
  6. Инициализация жизненного цикла Unity (`Awake()`, `OnEnable()`, `Start()`)
  7. Кадровые методы Unity (`Update()`, `FixedUpdate()`, `LateUpdate()`)
  8. Публичные методы
  9. Protected и Private методы
  10. Методы очистки жизненного цикла (`OnDisable()`, `OnDestroy()`, `Dispose()`)

## 2. Именование (Naming Conventions)

* **PascalCase**: Имена классов, структур, интерфейсов (с обязательным префиксом `I`), методов, свойств, перечислений (`enum`) и их элементов.
* **_camelCase**: Приватные и защищенные поля классов (начинаются с подчеркивания).
* **camelCase**: Параметры методов и локальные переменные в теле методов.
* **UPPER_SNAKE_CASE**: Константы (`const`) и статические поля только для чтения (`static readonly`).
* **Суффикс Async**: Все асинхронные методы, возвращающие `UniTask` или `Task`, обязаны иметь суффикс `Async` в своем названии.

---

## 3. SOLID принципы и Архитектурные границы

* **SRP (Single Responsibility / Разделение слоев)**:
  * **Визуальный слой (View)**: Классы `GameComponent`, `UIVBase`, `UIVWindow` занимаются исключительно рендерингом, анимациями, Spine, UI и звуками. В них запрещены расчеты игрового состояния, таймеры, сохранение прогресса или начисление очков.
  * **Слой логики (Logic)**: Системы `LogicSystem`, `FlowSystem` управляют правилами игры, но не хранят сессионные данные напрямую (используются `IParameter` и сервисы статистики) и не зависят от UI-библиотек.
* **Clean Architecture Boundaries**:
  * Классам логики (`LogicSystem`, `FlowSystem`), а также `IParameter` и `BaseConfig` **категорически запрещено** импортировать пространства имен отображения: `UnityEngine.UI`, `TMPro`, `Spine`, `UnityEngine.Video`.
* **DIP (Dependency Injection)**:
  * Зависимости между системами внедряются декларативно через `[InjectSystems]`.
  * Ссылки на визуальный слой (`GameComponent`) внедряются в системы через `[InjectComponent]`. Прямые вызовы `GetComponent` или `Find` для поиска вьюшек запрещены.
  * Запрещено создание систем через `new` или обращение к прямым синглтонам (типа `SoundManager.Instance`). Зависимости разрешаются через интерфейсы с помощью `LazySrv<T>` из локатора служб.

---

## 4. Жизненный цикл (Lifecycle) и Модульность

* **Изоляция игровых модулей**: Прямые ссылки на компоненты соседних игровых модулей запрещены. Модули общаются только через `EventBus<T>` или `IsolatedGameModuleService`.
* **base-вызовы**:
  * Метод `Dispose()`: вызов `base.Dispose()` должен быть строго **последней** строкой метода.
* **Module Stage API**: Перед завершением работы модуля в коде обязательно выставляется флаг `ModuleStageApi.IsModuleComplete = true`.
* **Callback Chains для логики**: Игровая бизнес-логика шагов/переходов строится на цепочках коллбэков. Использование асинхронности (`async/await`, `UniTask`) допускается только для чисто технических процессов (загрузки ресурсов, паузы на секунды, твины).
* **Системы логики без MonoBehaviour**: Классы `LogicSystem` не наследуются от `MonoBehaviour` и не содержат метод `Update()`. Они реализуют `IUpdatable` и обновляются через общий цикл платформы.
* **Исключение Magic Strings**: Строковые константы (ID звуков, ключи аналитики, анимации) запрещено писать текстом. Для полей ID в инспекторе должен использоваться атрибут `[ConstSelector("GroupName")]`. Любое ручное изменение автогенерируемого файла `Constants.cs` запрещено.
* **Использование готовой инфраструктуры**: Запрещено писать собственные менеджеры звука, системы локализации, менеджеры сцен или менеджеры ресурсов, если в платформе KBPro уже есть соответствующий сервис в ServiceLocator.

## 5. Производительность Unity (CPU, GPU и GC)

* **GetComponent в Update [Critical]**: Вызовы `GetComponent`, `GetComponentInChildren`, `TryGetComponent` запрещены в горячих путях (`Update()`, `FixedUpdate()`, `OnUpdate()`). Компоненты кэшируются один раз в `Awake()` или `Initialize()`.
* **Аллокации в кадровых методах**: В `Update()`, `FixedUpdate()`, `OnUpdate()` запрещены:
  * Использование **LINQ**-запросов (`.Where`, `.Select`, `.Any`).
  * Использование циклов `foreach` по динамическим коллекциям (используйте стандартный `for` по индексу).
  * **Конкатенация строк** и вызовы `.ToString()` (особенно для `enum` во избежание boxing). Для динамического текста используйте `ZString` или средства TextMeshPro.
* **TextMeshPro**: Использование стандартного UI компонента `UnityEngine.UI.Text` запрещено. Всегда используйте `TextMeshPro` (или `TextMeshProUGUI`). У TextMeshPro отключайте **Auto Size** во избежание тяжелого пересчета геометрии меша.
* **UI Raycast Target**: Отключайте `Raycast Target` у всех декоративных картинок (Image) и текстовых полей (TMP), которые не требуют кликов.
* **Layout Groups**: Избегайте глубокой вложенности компонентов авторазметки (`Vertical`, `Horizontal`, `Grid Layout Group`, `Content Size Fitter`).
* **Canvas Component**: Отключайте неиспользуемые панели UI через `canvas.enabled = false` вместо отключения самого GameObject.
* **Физика и FixedUpdate**: Физические вычисления и управление Rigidbody должны осуществляться **строго** в `FixedUpdate()`.
* **NonAlloc физические запросы**: Вместо `Physics.RaycastAll`, `Physics.OverlapSphere` используйте их безаллокационные аналоги: `Physics.RaycastNonAlloc`, `Physics.OverlapSphereNonAlloc`, передавая заранее выделенный массив под результаты.
* **Rigidbody Interpolation**: Включайте интерполяцию только на объектах, за которыми непосредственно следует камера.

## 6. Безопасность Рантайма (Runtime Safety & Integrity)

* **Null-проверки Unity-объектов**:
  * Всегда используйте явную проверку `if (obj != null)` или `if (obj == null)`.
  * **Запрещено** использовать null-условные операторы и операторы объединения с null для наследников `UnityEngine.Object` (например, `myMonoBehaviour?.DoSomething()` или `var x = targetRenderer ?? fallback`). Это приводит к непредсказуемым ошибкам в рантайме.
* **async void**:
  * Асинхронные методы без возвращаемого значения должны возвращать `async UniTaskVoid`.
  * Запуск таких методов должен производиться с вызовом `.Forget()`.
  * *Исключение*: Допускается `async void` в обработчиках событий Unity UI (кнопки), но тело метода должно оборачиваться в `try-catch`.
* **Cancellation Safety (Токены отмены)**:
  * Все асинхронные методы (`UniTask`, `Task`) обязаны принимать `CancellationToken token` и пробрасывать его во все дочерние вызовы.
  * При возникновении отмены (например, выход из модуля) задача должна прерываться (через `token.ThrowIfCancellationRequested()`).
* **Предотвращение утечек памяти (Подписки)**:
  * Все подписки на `EventBus<T>`, `MessageBroker` или реактивные стримы `UniRx` (`.Subscribe()`) должны сохраняться в `CompositeDisposable` и очищаться в `Dispose()` или `OnDestroy()`.
  * Подписки на обычные C# события (`+=`) обязательно должны иметь парные отписки (`-=`).
* **Использование пространств имен Editor [Critical]**:
  * Директивы `using UnityEditor;` и обращения к API редактора в рантайм-файлах должны быть строго обернуты в `#if UNITY_EDITOR ... #endif` или находиться в папках `Editor/`.
* **Поиск объектов**:
  * **Запрещено** использовать `GameObject.Find`, `GameObject.FindWithTag`, `Transform.Find` (динамический поиск) или `Object.FindObjectOfType` (и вариации) в рантайме.
* **Безопасное уничтожение объектов**:
  * При динамическом уничтожении GameObject-ов в представлениях (View) используйте:

    ```csharp
    if (Application.isPlaying) Destroy(target);
    else DestroyImmediate(target);
    ```

* **Безопасность физических триггеров**:
  * В методах `OnTriggerEnter`, `OnCollisionEnter` и их 2D аналогах обязательна проверка пришедшего объекта (по тегу, слою или через `TryGetComponent`) перед вызовом логики.
* **Блокировка ввода (Input Click-Through)**:
  * При кликах по 3D/2D объектам проверяйте, не перекрыт ли клик элементами UI (`EventSystem.current.IsPointerOverGameObject()`).
* **Локализация строк**:
  * Запрещено хардкодить русские/английские строки для текстовых UI полей. Текст должен выводиться строго через сервис локализации `LazySrv<ILocalizationService>` по ключам.
* **Логирование в релизе**:
  * В коммитах не должно оставаться временных/отладочных вызовов `Debug.Log`, `Debug.LogWarning` или `Debug.LogError`. Для диагностических проверок использовать `Debug.Assert` или оборачивать вызовы в `#if UNITY_EDITOR` / `#if DEBUG`.
* **Контроль секретов [Blocker]**:
  * В коде, конфигурациях (`BaseConfig`) или текстовых ассетах категорически запрещено жестко прописывать пароли, API-ключи, токены авторизации или адреса серверов.

## 7. Ресурсы, Префабы и Импорт Ассетов

* **Missing Script / Missing References [Blocker]**:
  * Полный запрет на коммиты с префабами (`.prefab`), сценами (`.unity`) или ScriptableObject (`.asset`), содержащими компоненты с битыми ссылками на C# скрипты или битые ссылки на другие ресурсы.
* **ComponentAccessor во View**:
  * Для быстрого доступа к дочерним визуальным элементам (TMP Text, Image, Spine Skeleton) внутри префабов представлений должен быть настроен `ComponentAccessor`. Поиск через `GetComponentInChildren` или `transform.Find` в рантайме для Views запрещен.
* **Размеры текстур**:
  * Размеры всех текстур (ширина и высота) должны быть строго кратными степеням двойки (Power of 2).
* **Именование ассетов**:
  * В названиях файлов ассетов, папок и подпапок категорически запрещено использовать кириллицу и пробелы. Используйте нижнее подчеркивание `_`.
* **Настройки импорта текстур**:
  * UI/2D: `Sprite (2D and UI)`, 3D-модели: `Default`.
  * Мобильные: `Override` для Android/iOS с форматом сжатия **ASTC 6x6** или **ASTC 4x4**.
  * Непрозрачные текстуры: `Alpha Source -> None` и снятая галочка `Keep Alpha`.
  * UI/2D-спрайты: `Generate Mip Maps` должна быть выключена.
  * Всегда выключать `Read/Write Enabled` для текстур (за исключением случаев динамического изменения пикселей через C#).
* **UI Slicing (9-slice)**:
  * Для масштабируемых элементов интерфейса используйте механизм 9-slice.
* **Аудио импорт**:
  * **Streaming** — для длинных фоновых музыкальных треков.
  * **Decompress on Load** — для коротких звуковых эффектов (<3 секунд).
  * Сжатие: Музыка — `Vorbis` (или `AAC` для iOS) с качеством 50–70%. SFX — формат `ADPCM`.
  * По позиционному звуку (3D): Всегда включайте галочку `Force to Mono`.
* **Метафайлы (`.meta`)**:
  * Каждому добавленному файлу ресурса (текстура, звук, скрипт) должен соответствовать коммитящийся `.meta` файл с корректными связями.
