# Свод правил: Руководство по оптимизации Unity-приложений

Этот документ объединяет ключевые технические правила оптимизации камер, рендеринга, интерфейса, аудио и физики на мобильных и десктопных платформах в проектах KBPro.

---

## 1. Камера и Рендеринг (Camera & Rendering)

### Оптимизация Камер
* **Минимум активных камер**: Используйте в сцене в идеале одну основную камеру. Второстепенные камеры должны быть отключены (`enabled = false`) или переведены на уменьшенный Viewport Rect, если они не нужны постоянно.
* **Canvas Screen Space - Overlay**: Для интерфейса используйте режим Canvas `Screen Space - Overlay` вместо создания отдельной UI-камеры.
* **Clear Flags**: 
  - На главной камере используйте `Solid Color` или `Skybox`.
  - Для оверлейных (дополнительных) камер используйте `Depth Only` или `Don't Clear` (для предотвращения лишней очистки цветового буфера).
* **Clipping Planes**: 
  - Настраивайте `Near plane` как можно дальше (0.1–0.3), а `Far plane` урезайте до разумного игрового минимума (например, 50–150 вместо 1000 по умолчанию). Это повышает точность буфера глубины и устраняет мерцание текстур (Z-fighting).

### Рендеринг и SRP
* **Occlusion Culling**: Должно быть запечено для всех сцен с большим количеством статической геометрии, закрывающей друг друга.
* **SRP Batcher**: Убедитесь, что все шейдеры совместимы с SRP Batcher для минимизации количества вызовов отрисовки (Draw Calls).
* **Пост-обработка**: Отключайте Bloom, Depth of Field, Motion Blur и SSAO для мобильных платформ. Допускается использование максимум 1-2 легких эффектов (Color Grading).
* **Сглаживание**: Ограничивайте MSAA до 2x или 4x на высоких настройках, для слабых девайсов отключайте полностью или используйте легкий FXAA.

## 2. Оптимизация интерфейса (UI Optimization)

* **Sprite Atlases (Атласы)**: Все спрайты интерфейса должны быть сгруппированы в Sprite Atlas по экранам или функциональным группам для батчинга вызовов отрисовки.
* **Raycast Target**: **Отключайте** галочку `Raycast Target` на всех декоративных картинках (Image) и текстовых полях (TMP), которые не требуют кликов от пользователя. Оставленный включенным Raycast Target заставляет Unity проводить дорогостоящий Graphic Raycast по всей иерархии UI при каждом тапе по экрану.
* **Вложенность Layout Groups**: Избегайте глубокой вложенности компонентов авторазметки (`Vertical Layout Group`, `Horizontal Layout Group`, `Grid Layout Group`, `Content Size Fitter`). При изменении одного дочернего элемента пересчитывается вся цепочка родителей, что вызывает просадки FPS (UI Rebuild).
* **Canvas Component**: Отключайте неиспользуемые панели UI через `canvas.enabled = false` вместо отключения самого GameObject. Это сохраняет ресурсы процессора на выключение и включение объектов, но прекращает рендеринг Canvas.

## 3. Оптимизация звука (Audio Optimization)

* **Load Type**:
  - **Streaming** — для длинных фоновых музыкальных треков и амбиентов. Музыка будет считываться с диска по мере воспроизведения, экономя оперативную память (RAM).
  - **Decompress on Load** — для коротких, часто воспроизводимых звуковых эффектов (SFX) длительностью менее 2-3 секунд. Звук распаковывается в RAM один раз для мгновенного проигрывания без задержек.
* **Сжатие (Compression Format)**:
  - Фоновая музыка: формат `Vorbis` (или `AAC` для iOS) с качеством сжатия 50–70%.
  - Звуковые эффекты: формат `ADPCM` (для быстрого декодирования процессором).
* **Force to Mono**:
  - Всегда включайте галочку `Force to Mono` для всех позиционных 3D-звуков. Стереофайлы занимают в 2 раза больше места и не могут позиционироваться в 3D пространстве корректно. Оставляйте стерео только для фоновой музыки (2D).

## 4. Оптимизация физики (Physics Optimization)

* **FixedUpdate**: Физические вычисления и изменение сил Rigidbody должны производиться **строго** внутри метода `FixedUpdate()`, а не `Update()`.
* **Rigidbody Interpolation**: Включайте интерполяцию (`Interpolate` или `Extrapolate`) только на объектах, за которыми непосредственно следует камера (персонаж игрока), чтобы сгладить движение. На остальных физических телах интерполяция должна быть выключена.
* **Layer Collision Matrix**: Настраивайте матрицу столкновений слоев в настройках проекта (`Physics/Physics2D Settings`). Слои, которые не должны физически сталкиваться друг с другом (например, триггеры сбора монеток и препятствия), должны быть отключены.
* **NonAlloc физические запросы**: Вместо методов `Physics.RaycastAll`, `Physics.OverlapSphere` используйте их безаллокационные аналоги: `Physics.RaycastNonAlloc`, `Physics.OverlapSphereNonAlloc`, передавая заранее выделенный массив под результаты. Это исключает выделение памяти GC на каждый физический запрос.
