# Архитектурные правила ServiceLocator и LazySrv

Этот справочник описывает стандарты управления зависимостями в KBPro с использованием статического контейнера `ServiceLocator` и ленивого связывания `LazySrv<T>`.

---

## 1. Роль ServiceLocator в архитектуре

**ServiceLocator** — это центральный статический реестр зависимостей (`Dictionary<Type, IService>`), который используется во всем Core-слое платформы KBPro.

- Отказ от классического рантайм-сканирования (как в Zenject) сделан ради максимальной производительности на мобильных платформах и консолях.
- Доступ к сервисам из локатора осуществляется синхронно: `ServiceLocator.GetService<ITimerService>()`.

### Интерфейс IService
Все глобальные службы в игре обязаны реализовать интерфейс `IService` (или наследоваться от MonoBehaviour, реализующего `IService`):
```csharp
public interface IService : IDisposable
{
    Type RegisterType { get; }
    void Initialize();
}
```
- Свойство `RegisterType` указывает, под каким типом-ключом (обычно интерфейсом) сервис регистрируется в локаторе (например, `typeof(ISoundSystem)`).

---

## 2. Ленивая инициализация через LazySrv<T>

Для предотвращения проблем недерминированного порядка инициализации (когда сервис `A` пытается получить сервис `B` во время загрузки, но `B` еще не зарегистрирован) все зависимости в коде должны объявляться через класс-обертку `LazySrv<T>`.

- **Порядок работы**:
  1. При объявлении поля создается легкая обертка: `private LazySrv<ISoundSystem> _audio = new();`
  2. Первое обращение к свойству `_audio.Value` запрашивает сервис из `ServiceLocator` и кэширует его.
  3. В методе `Dispose()` обязательно освобождать обертку: `_audio.Dispose();`.

```csharp
using KBP.CORE;
using System;

public class GameplayPresenter : IDisposable
{
    // Объявление ленивой зависимости
    private LazySrv<ISoundSystem> _audio = new LazySrv<ISoundSystem>();

    public void OnPlayerWin()
    {
        // Разрешение зависимости при первом обращении
        _audio.Value.PlaySound("win_fanfare");
    }

    public void Dispose()
    {
        // Обязательная очистка (зануляет внутреннюю ссылку на сервис)
        _audio.Dispose();
    }
}
```

## 3. Встроенные микро-сервисы фреймворка

При написании игровых систем вы можете использовать следующие глобальные сервисы, уже зарегистрированные в `ServiceLocator`:

1. **`ITimerService`**: Предоставляет централизованный кадр-апдейт (`Update/FixedUpdate`) и отложенные коллбеки `DelayCallback(duration, callback)`.
2. **`ISoundSystem`**: Управление воспроизведением музыки, SFX-звуков и озвучкой с привязкой к микшерам.
3. **`ICameraService`**: Управление Cinemachine-камерами (зум, слежение, переключение ракурсов).
4. **`IStatisticService`**: Сбор аналитических событий и сохранение прогресса игрока.
5. **`IPoolService`**: Оптимизированное переиспользование объектов (партиклы, искры, капли) для исключения рантайм-аллокаций.
