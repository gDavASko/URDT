# Bitrix24 Import API Contract

> Источник: Регламент API импорта задач Bitrix24 KBPro.

## Эндпоинты (от базового вебхука)

Базовый URL берётся из `KBPRO_BITRIX24_WEBHOOK_BASE`. Методы добавляются к нему:

| Назначение | Метод |
|------------|-------|
| Создать задачу | `<base>/tasks.task.add.json` |
| Проставить теги | `<base>/task.item.update.json` (legacy) |

## Двухшаговый процесс (на каждую задачу)

### Шаг 1 — `tasks.task.add`
Тело: `{ "fields": { TITLE, DESCRIPTION, RESPONSIBLE_ID, PRIORITY, ALLOW_TIME_TRACKING, GROUP_ID, UF_TASK_CAPACITY } }`.
Ответ при успехе содержит `result.task.id` — это id созданной задачи.

> Поле `TAGS` на этом шаге **не отправляется**.

### Шаг 2 — `task.item.update` (только если у задачи есть теги)
Тело — **позиционный массив**: `[ <taskId>, { "TAGS": ["tag1", "tag2"] } ]`.
Это единственный надёжный способ сохранить массив тегов через вебхук (legacy API).

## Кодировка запросов

- JSON-файл читается как UTF-8.
- Тело каждого запроса кодируется в байты UTF-8 и отправляется с `Content-Type: application/json; charset=utf-8`.

## Обязательные значения полей (контракт проекта)

`GROUP_ID` = целевой Bitrix project/workgroup из запроса пользователя (`100` для «Ну Погоди! Роботы`, `94` только старый пример песочницы), `RESPONSIBLE_ID = 66` до Gantt-переназначения, `PRIORITY` ∈ {1,2,3}, `ALLOW_TIME_TRACKING = "1"`.
Менять проект/группу без явного указания пользователя нельзя — это привязка к конкретному воркспейсу/группе Bitrix.

`UF_TASK_CAPACITY` (или системный API-ключ `UF_TASKS_TASK_1783529349965`) обязателен для каждой задачи. Это оценка сложности в человекочасах как целое число: `1`, `4`, `8`, `20`, `77`. Человекодни, дробные значения и запятая как разделитель запрещены. Если исходный источник содержит человекодни, перед записью в Bitrix конвертировать один раз: `ceil(ч-д * 8)`.

## Правило планирования Ганта

Перед созданием, переносом или переназначением задач нужно проверить расписание целевого исполнителя. Рабочее окно планирования: `10:00–18:00 МСК`, ровно `8` рабочих часов. На один рабочий день одного исполнителя можно поставить суммарно не более `8` человекочасов. В Bitrix обязательно ставить `DURATION_TYPE="hours"` и `DURATION_PLAN` равный оценке в человекочасах; системное поле `UF_TASKS_TASK_1783529349965` синхронизировать с тем же числом часов. Если новая задача должна идти первой, все последующие задачи этого исполнителя сдвигаются вперед; запрещено просто назначать новую задачу поверх уже запланированной работы. Задача на `20` человекочасов занимает 2 полных рабочих дня и еще 4 часа; следующая задача стартует сразу после окончания предыдущей.

Видимые стрелки в Ганте требуют `DEPENDS_ON` у следующей задачи через legacy `task.item.update`, например `[nextTaskId, { "DEPENDS_ON": [previousTaskId] }]`. `task.dependence.add` может создать скрытую связь без стрелки и не считается достаточным. Порядок записи всегда такой: сначала даты/исполнитель/оценка/`DURATION_PLAN`, затем `DEPENDS_ON`, затем проверка через `task.item.getdata`.

## Идемпотентность

Её нет. Повторный запуск создаёт **дубликаты** задач. Перед повторным запуском — подтверждение пользователя и, при необходимости, ручная чистка ранее созданных задач.
