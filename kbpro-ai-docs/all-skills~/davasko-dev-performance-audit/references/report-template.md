# Report Template v2 (final analyst output — RUSSIAN)

The final analyst writes `report.md` in Russian following this exact structure
(plan v2 §8а: three readers — the lead, upper management, 1:1 conversations).
Section length limits are hard caps (token economy). Every number must trace to
`metrics-summary.json`; every claim about code must carry evidence refs
(`sha:file`) from `rework_links` / `llm_scores.evidence`.

The v1 "seven axes" section is REMOVED (axes were unit-mixing composites).
Metrics are reported in groups with guardrail pairs.

---

# Аудит эффекта нововведения: {{INNOVATION_NAME}} — {{AUTHOR_DISPLAY}}

> Период: {{FROM}} — {{TO}} · Фазы: {{PHASE_LIST}} · Прогон: {{RUN_DATE}}
> Флаги: {{FLAGS}}

## 1. Management summary (≤ 8 предложений, без технических деталей)

Для вышестоящего руководства: что внедрялось и когда; что изменилось по трём
приоритетам — скорость поставки, качество/переделки, рост и самостоятельность;
итоговый вердикт **positive / neutral / negative / indeterminate** с уровнем
уверенности. Честно выбирать «indeterminate», когда дельты объяснимы
конфаундерами (смена профиля задач, отпуска, LOW_SAMPLE, adoption только по
датам).

## 2. Пары «скорость ↔ качество» по фазам

Таблица guardrail-пар из `guardrail_pairs`: каждая строка — пара, колонки —
фазы, ячейка «скорость / качество». Под таблицей 1–2 предложения на пару.
ЗАПРЕЩЕНО делать вывод «стало быстрее» без упоминания парной метрики качества.

## 3. Динамика (ITS-lite)

По ключевым метрикам из `m20.deltas_pm`: дельта за месяц + наклоны трендов
внутри фаз (`slopes_prev` / `slopes_cur`). Отмечать случаи, когда «улучшение
после внедрения» было продолжением тренда, начавшегося ДО внедрения.
Качественные метрики — только по правилу непересечения полос
(`qualitative_trends`).

## 4. Качественные наблюдения (LLM-полосы)

Полосы m6/m7/m14/m17/m18 с уверенностью и 1–2 evidence-ссылками на полосу.
`N/A` показывается как `N/A`, не как 0.

## 5. Переделки и стабильность (кандидаты для проверки человеком)

`m8.self_fix_ratio`, `m9.ratio`, `m16` + до 5 примеров из `rework_links`
(origin sha → fix sha, файл, возраст строк). Прямо писать: это кандидаты
для просмотра, не вердикт о надёжности.

## 6. Темы для 1:1 (если ATTENTION непуст)

Каждое отклонение от групповой динамики — как вопрос для разговора
(«стоит спросить, с чем связано изменение X»), не как оценка. Указывать
медиану группы для контекста.

## 7. Вердикт по сотруднику

`{ verdict, reason }` — одно предложение обоснования, какие метрики дали
вердикт и какие ограничения его ослабляют.

## 8. Ограничения и дисклеймер (фиксированный блок)

- Все объёмные метрики нормированы «за месяц»; фазы разной длины сравнимы.
- Git-данные видят следы работы, не её содержание и не сложность задач.
- Сравнения только «сам с собой»; таблицы людей не являются рейтингом.
- Отчёт не предназначен для зарплатных/кадровых решений.
- Перечислить активные флаги: {{FLAGS}} и что каждый означает для выводов.
