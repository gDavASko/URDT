# Полный каталог 2D-механик: Часть 1 (M01 – M16)

Данный документ содержит исчерпывающие описания, структуру маячков, физические и геометрические формулы, ловушки и пошаговые алгоритмы прохождения для механик с M01 по M16. Вся информация полностью самодостаточна и не требует внешних ссылок.

## M01: Snap-to-Slot Puzzle (Базовое позиционирование деталей)

### 1. Суть механики
На экране расположены цветные геометрические детали (`M01_DraggableTile_*`) и приемные пазы (`M01_DropSlot_*`). Игрок должен перетащить каждую валидную деталь в соответствующий паз. При отпускании внутри радиуса захвата ($R_{\text{snap}} = 80$ px) деталь защелкивается и блокируется.

### 2. Маячки URDT
- `M01_SnapToSlot`: `Urdt2DModuleTarget` — общий прогресс `ProgressNormalized`, статус `IsCompleted`.
- `Item_Circle`, `Item_Square`, `Item_Triangle`: `Urdt2DDraggableTarget` — перетаскиваемые детали. Поля: `ItemId`, `IsJunk`, `IsSnapped`, `ScreenCenter`.
- `Item_Junk`: `Urdt2DDraggableTarget` — мусорная деталь со знаком 'X' (`IsJunk == true`), не подходит никуда.
- `Slot_Circle`, `Slot_Square`, `Slot_Triangle`: `Urdt2DSlotTarget` — гнезда. Поля: `SlotId`, `IsOccupied`, `ScreenCenter`.
- `Obstacle_Barrier`: статическое препятствие между лотком и гнездами.

### 3. Ловушки и решения
- **Ловушка**: Попытка положить деталь `Item_Junk` приводит к отскоку и блокировке прогресса.
  *Решение*: Фильтрация по флагу `!item.IsJunk`.
- **Ловушка**: Драг по прямой линии через `Obstacle_Barrier` может сбить деталь или вызвать коллизию.
  *Решение*: Прокладывать траекторию через промежуточную точку обхода или высокий подъем по оси Y.
- **Ловушка**: Драг в 1 шаг не вызывает события `IDragHandler`.
  *Решение*: Использовать интерполяцию минимум на 20 шагов.

### 4. Пошаговый алгоритм
1. Запросить активные маячки через `query()`.
2. Найти все элементы, где `components.Urdt2DDraggableTarget.IsJunk == false` и `IsSnapped == false`.
3. Для каждого предмета найти слот, где `slot.SlotId == item.ItemId`.
4. Сгенерировать траекторию: от `item.ScreenCenter` через безопасную дугу к `slot.ScreenCenter`.
5. Выполнить `drag(from, to, steps: 20)`.
6. Ожидать 300 мс, запросить `inspect('M01_SnapToSlot')`, проверить рост `ProgressNormalized`.

## M02: Multi-Container Sorting (Сортировка по контейнерам)

### 1. Суть механики
Множество предметов различной формы и цвета (красные треугольники, синие круги, зеленые квадраты) появляются на конвейере. Требуется рассортировать их по соответствующим контейнерам. Неверно сброшенный предмет отскакивает с ошибкой.

### 2. Маячки URDT
- `M02_ContainerSorting`: `Urdt2DModuleTarget` — статус завершения.
- `Item_*` (например, `Item_RedTriangle`): `Urdt2DDraggableTarget` — тип детали в `Category` или `ItemId`.
- `Bin_Red`, `Bin_Blue`, `Bin_Green`: `Urdt2DSlotTarget` — контейнеры с атрибутом `AcceptedType`.

### 3. Ловушки и решения
- **Ловушка**: Пересечение траекторий при быстром драге приводит к ложному сбросу в соседний контейнер.
  *Решение*: Точный драг строго в геометрический центр целевого контейнера.

### 4. Пошаговый алгоритм
1. Получить список неотсортированных предметов через `query()`.
2. Для каждого предмета сопоставить `item.Category` с `bin.AcceptedType`.
3. Выполнить `drag(item.ScreenCenter, bin.ScreenCenter, steps: 15)`.
4. Выдержать паузу 250 мс, убедиться в увеличении счетчика контейнера.

## M03: Weight Comparator (Калибровка весов)

### 1. Суть механики
Двухчашечные рычажные весы. На левой чаше находится неизвестный эталонный груз ($W_{\text{target}} = 350$ г). На правой чаше игрок должен собрать комбинацию калибровочных гирь ($50$ г, $100$ г, $200$ г) так, чтобы разница весов не превышала $\Delta W \le 10$ г.

### 2. Маячки URDT
- `M03_WeightComparator`: `Urdt2DModuleTarget`.
- `Weight_50g`, `Weight_100g`, `Weight_200g`: `Urdt2DDraggableTarget`.
- `Scale_RightPan`: `Urdt2DSlotTarget`.
- `ScaleReadout`: `UrdtUiTextTarget` — индикатор баланса.

### 3. Ловушки и решения
- **Ловушка**: Перегруз чаши (например, 200 + 200) блокирует механизм весов.
  *Решение*: Жадный алгоритм subset-sum: $200\text{ г} + 100\text{ г} + 50\text{ г} = 350\text{ г}$.

### 4. Пошаговый алгоритм
1. Перетащить `Weight_200g` на `Scale_RightPan`.
2. Перетащить `Weight_100g` на `Scale_RightPan`.
3. Перетащить `Weight_50g` на `Scale_RightPan`.
4. Опросить `ScaleReadout`, убедиться в получении сообщения «Сбалансировано!», прогресс 100%.

## M04: Multi-Layer Attachment (Послойная топологическая сборка)

### 1. Суть механики
Многослойный электронно-механический узел. Детали должны устанавливаться в строго монотонном порядке слоев: Слой 1 (Базовая плата) $\to$ Слой 2 (Прокладка) $\to$ Слой 3 (Процессор) $\to$ Слой 4 (Крышка).

### 2. Маячки URDT
- `M04_MultiLayerAttachment`: `Urdt2DModuleTarget`.
- `Part_Core` / `Layer_1_Base`: `Urdt2DDraggableTarget` с индексом слоя `LayerIndex = 1`.
- `Part_Armor` / `Layer_2_Gasket`: `LayerIndex = 2`.
- `Part_Head` / `Layer_3_Processor`: `LayerIndex = 3`.
- `Part_Battery` / `Layer_4_Cover`: `LayerIndex = 4`.
- `Socket_Assembly`: `Urdt2DSlotTarget`.

### 3. Ловушки и решения
- **Ловушка**: Попытка установить слой 3 до установки слоя 2 приводит к отскоку детали.
  *Решение*: Строго монотонная сортировка деталей по `LayerIndex` перед началом действий.

### 4. Пошаговый алгоритм
1. Отсортировать детали по возрастанию номера слоя $L \in [1, 2, 3, 4]$.
2. Последовательно перетащить каждую деталь `drag(part.ScreenCenter, socket.ScreenCenter, steps: 20)`.
3. Делать паузу 400 мс между слоями для завершения анимации монтажа.

## M05: Timeline Sequencer (Хронологическая шкала кадров)

### 1. Суть механики
Четыре кадра жизненного цикла (Яйцо $\to$ Гусеница $\to$ Куколка $\to$ Бабочка) перемешаны в лотке. Их необходимо расставить в правильном хронологическом порядке в слоты с 1 по 4.

### 2. Маячки URDT
- `M05_TimelineSequencer`: `Urdt2DModuleTarget`.
- `Frame_1_Egg`, `Frame_2_Caterpillar`, `Frame_3_Chrysalis`, `Frame_4_Butterfly`: `Urdt2DDraggableTarget`.
- `TrackSlot_1`, `TrackSlot_2`, `TrackSlot_3`, `TrackSlot_4`: `Urdt2DSlotTarget`.

### 3. Ловушки и решения
- **Ловушка**: Попытка вставить карточку между уже установленными может вытолкнуть соседнюю.
  *Решение*: Заполнять шкалу строго слева направо: слот 1, затем 2, затем 3, затем 4.

### 4. Пошаговый алгоритм
1. Сопоставить кадры со слотами по их порядковому номеру $k \in [1..4]$.
2. Для каждого $k$: `drag(Frame_k, TrackSlot_k, steps: 15)`.
3. Пауза 300 мс после каждого размещения; проверка `IsCompleted == true`.

## M06: Node Pairing (Соединение узлов графа проводами)

### 1. Суть механики
Коммутационная панель: 4 источника сигналов слева (`Pin_Src_1..4`) и 4 приемника справа (`Pin_Tgt_1..4`). Необходимо соединить парные контакты патч-кордами.

### 2. Маячки URDT
- `M06_NodePairing`: `Urdt2DModuleTarget`.
- `Pin_Src_1` .. `Pin_Src_4`: `Urdt2DDraggableTarget` — точки захвата проводов.
- `Pin_Tgt_1` .. `Pin_Tgt_4`: `Urdt2DSlotTarget` — приемные клеммы.

### 3. Ловушки и решения
- **Ловушка**: Отпускание провода на расстоянии более 110 px от центра целевого пина сбрасывает провод.
  *Решение*: Завершать драг строго в центре целевого пина `targetPin.ScreenCenter`.

### 4. Пошаговый алгоритм
1. Для каждой пары $(i)$: определить координаты `src = Pin_Src_i.ScreenCenter` и `tgt = Pin_Tgt_i.ScreenCenter`.
2. Выполнить `drag(src, tgt, steps: 20)`.
3. Пауза 200 мс для фиксации штекера; повторить для всех 4 контактов.

## M07: Wobble & Snap (Фиксация с гашением колебаний)

### 1. Суть механики
Маятник-осциллятор с пружинным подвесом. При перетаскивании объект раскачивается по гармоническому закону. Защелкивание в приемное гнездо происходит ТОЛЬКО при остаточной скорости $V < 12$ px/s.

### 2. Маячки URDT
- `M07_WobbleAndSnap`: `Urdt2DModuleTarget`.
- `WobblePendulum`: `Urdt2DDraggableTarget`.
- `CaptureBasin`: `Urdt2DSlotTarget` (центр $X=640, Y=320$).

### 3. Ловушки и решения
- **Ловушка**: Быстрое перемещение и резкий `pointer_up` выбрасывают маятник из чаши за счет упругой отдачи пружины.
  *Решение*: Dwell-пауза! Переместить курсор в центр `CaptureBasin`, удерживать неподвижно 450–500 мс, и только затем отпустить.

### 4. Пошаговый алгоритм
1. Переместить маятник: `drag(WobblePendulum.ScreenCenter, CaptureBasin.ScreenCenter, steps: 25)`.
2. Удерживать курсор в конечной точке 500 мс без движения.
3. Отправить `pointer_up(CaptureBasin.ScreenCenter)`.
4. Проверить затухание колебаний и фиксацию замка.

## M08: Waypoint Tracking (Проводка зонда по каналу контрольных точек)

### 1. Суть механики
Узкий извилистый канал шириной $W = 45$ px с 5 последовательными контрольными точками ($W_1 \dots W_5$). Зонд должен пройти по всем точкам по порядку, не выходя за границы стенок канала.

### 2. Маячки URDT
- `M08_WaypointTracking`: `Urdt2DModuleTarget`.
- `WaypointProbe`: `Urdt2DDraggableTarget` — управляемый курсор.
- `Waypoint_1` .. `Waypoint_5`: `Urdt2DInteractiveAreaTarget` — вейпоинты.

### 3. Ловушки и решения
- **Ловушка**: Прямолинейный прыжок между $W_1$ и $W_3$ пересекает границу канала и вызывает мгновенный сброс прогресса.
  *Решение*: Трассировка кусочно-линейного сплайна `press_move` строго через центры всех 5 точек.

### 4. Пошаговый алгоритм
1. Запросить координаты всех точек $P = [W_1.\text{pos}, W_2.\text{pos}, W_3.\text{pos}, W_4.\text{pos}, W_5.\text{pos}]$.
2. Вызвать `press_move({ path: P, stepsPerSegment: 12 })`.
3. Дождаться отчета об успешном прохождении финальной точки.

## M09: Coverage Accumulator (Равномерная очистка поверхности)

### 1. Суть механики
Поверхность покрыта сеткой загрязненных ячеек. Губка/щетка с радиусом воздействия $R_{\text{brush}} = 50$ px должна стереть грязь так, чтобы суммарное покрытие превысило $95\%$.

### 2. Маячки URDT
- `M09_CoverageAccumulator`: `Urdt2DModuleTarget`.
- `SpongeBrush`: `Urdt2DDraggableTarget`.
- `DirtGrid`: прямоугольная область очистки.

### 3. Ловушки и решения
- **Ловушка**: Хаотичные круговые движения оставляют грязные пятна по углам.
  *Решение*: Растровое змейкообразное сканирование (Raster Scan) с шагом смещения $\Delta Y = 0.8 \cdot R_{\text{brush}}$.

### 4. Пошаговый алгоритм
1. Вычислить границы рабочей зоны $(X_{\min}, Y_{\min}) \dots (X_{\max}, Y_{\max})$.
2. Построить траекторию змейки: слева-направо, шаг вниз, справа-налево, шаг вниз.
3. Выполнить `press_move({ path: snakePoints, stepsPerSegment: 8 })`.
4. Проверить `ProgressNormalized >= 0.95`.

## M10: Timed Accumulator (Накопление заряда с удержанием)

### 1. Суть механики
Кнопка зарядного терминала. При удержании нажатия уровень энергии растет со скоростью $R = 25\%/\text{сек}$. Необходимо отпустить кнопку, когда шкала находится в диапазоне $[90\%, 100\%]$. Перелив выше $100\%$ приводит к перегрузке и сбросу.

### 2. Маячки URDT
- `M10_TimedAccumulator`: `Urdt2DModuleTarget`.
- `HoldButton`: `Urdt2DInteractiveAreaTarget` / `ButtonTarget`.
- `EnergyGauge`: индикатор заряда.

### 3. Ловушки и решения
- **Ловушка**: Опоздание с отпусканием на 100 мс вызывает срыв в перегрузку.
  *Решение*: Точный расчет времени удержания: $T = \frac{95\%}{25\%/\text{сек}} = 3.8$ секунды.

### 4. Пошаговый алгоритм
1. Отправить `pointer_down(HoldButton.ScreenCenter)`.
2. Выдержать паузу ровно $3800$ мс.
3. Отправить `pointer_up(HoldButton.ScreenCenter)`.
4. Убедиться в фиксации зеленого сектора заряда.

## M11: Cone Emitter (Секторный эмиттер и наведение)

### 1. Суть механики
Вращающаяся турель стреляет импульсами в секторе разброса $\pm 15^\circ$. Необходимо поразить 3 движущиеся мишени, стреляя только в моменты, когда мишень находится внутри конуса поражения.

### 2. Маячки URDT
- `M11_ConeEmitter`: `Urdt2DModuleTarget`.
- `TurretAim`: поворотное орудие.
- `FireTarget_1..3`: мишени с вектором скорости $\vec{V}$.
- `BtnFire`: кнопка залпа.

### 3. Ловушки и решения
- **Ловушка**: Стрельба вдогонку мишени приводит к промаху из-за времени полета снаряда.
  *Решение*: Расчет упреждения $\Delta \theta = \frac{|\vec{V}| \cdot t_{\text{flight}}}{R}$.

### 4. Пошаговый алгоритм
1. Для каждой мишени: рассчитать момент пересечения конуса турели.
2. Повернуть прицел на угол упреждения.
3. Отправить `click(BtnFire.ScreenCenter)` в расчетный момент.

## M12: Angular Delta Tracker (Круговой энкодер / Ручка настройки)

### 1. Суть механики
Круглая ручка-потенциометр. Требуется повернуть её на заданный угол $\Theta_{\text{target}} = 270^\circ$ по часовой стрелке. При резких линейных драгах угол срывается.

### 2. Маячки URDT
- `M12_AngularDeltaTracker`: `Urdt2DModuleTarget`.
- `RotaryWheel`: `Urdt2DInteractiveAreaTarget` (центр $C = (X_c, Y_c)$, радиус $R = 120$ px).

### 3. Ловушки и решения
- **Ловушка**: Прямолинейный drag из точки $0^\circ$ в точку $180^\circ$ через центр ручки вызывает неопределенность знака арктангенса и сброс угла.
  *Решение*: Драг по дуге окружности: разбиение на 8 хорд $P_k = (X_c + R \cos \theta_k, Y_c + R \sin \theta_k)$.

### 4. Пошаговый алгоритм
1. Вычислить 8 промежуточных точек по окружности от $0^\circ$ до $270^\circ$.
2. Передать массив точек в `press_move({ path: arcPoints, stepsPerSegment: 6 })`.
3. Убедиться в достижении калибровочной отметки.

## M13: Lane Switcher Runner (Трехполосный раннер с уклонением)

### 1. Суть механики
Персонаж непрерывно движется вперед по 3 полосам (Левая: $X=440$, Центр: $X=640$, Правая: $X=840$). Навстречу движутся препятствия. Необходимо вовремя перестраиваться между полосами.

### 2. Маячки URDT
- `M13_LaneSwitcherRunner`: `Urdt2DModuleTarget`.
- `RunnerPlayer`: `Urdt2DDraggableTarget` — позиция игрока.
- `Obstacle_*`: препятствия с текущей Y-координатой и полосой `LaneIndex` (0, 1, 2).
- `Lane_0`, `Lane_1`, `Lane_2`: целевые зоны полос.

### 3. Ловушки и решения
- **Ловушка**: Поздняя реакция при $Y_{\text{obstacle}} < 200$ px не оставляет времени на анимацию перестроения (требуется 150 мс).
  *Решение*: Сканирование препятствий на упреждающей дистанции $Y \in [350, 600]$ px.

### 4. Пошаговый алгоритм
1. В цикле опроса: анализировать ближайшее препятствие по ходу движения игрока.
2. Если полоса игрока перекрыта, выбрать свободную соседнюю полосу.
3. Отправить быстрый клик по `Lane_target.ScreenCenter` или короткий свайп в сторону свободной полосы.
4. Удерживать безопасную полосу до выхода из опасной зоны.

## M14: Slingshot Impulser (Запуск из рогатки с натяжением)

### 1. Суть механики
Рогатка с эластичным жгутом. Требуется сбить пирамиду банок (`TargetCan_*`), оттянув снаряд назад и отпустив.

### 2. Маячки URDT
- `M14_SlingshotImpulser`: `Urdt2DModuleTarget`.
- `SlingshotAnchor`: опорная точка крепления рогатки $(X_0, Y_0)$.
- `SlingshotProjectile`: снаряд в ложементе.
- `TargetCan_1..3`: банки-мишени.

### 3. Ловушки и решения
- **Ловушка**: Драг снаряда В СТОРОНУ МИШЕНИ — снаряд летит назад!
  *Решение*: Вектор натяжения направлен СТРОГО ПРОТИВОПОЛОЖНО направлению на цель: $\vec{T} = -\alpha \cdot (\vec{P}_{\text{target}} - \vec{P}_{\text{anchor}})$.

### 4. Пошаговый алгоритм
1. Вычислить направление на центр пирамиды банок.
2. Вычислить точку максимального натяжения жгута в обратную сторону: $(X_{\text{pull}}, Y_{\text{pull}})$.
3. Выполнить `drag(SlingshotProjectile.ScreenCenter, { x: X_pull, y: Y_pull }, steps: 15)`.
4. Снаряд автоматически отпускается в конце драга, нанося импульсный удар.

## M15: Timing Interceptor (Перехват движущейся цели)

### 1. Суть механики
Цель осциллирует горизонтально с периодом $T = 2.4$ с. По экрану движется визир прицела. Игрок должен нажать кнопку перехвата ровно в момент совпадения координат с допуском $\Delta X \le 25$ px.

### 2. Маячки URDT
- `M15_TimingInterceptor`: `Urdt2DModuleTarget`.
- `TargetMoving`: динамический маяк цели.
- `SweepReticle`: движущийся визир.
- `BtnIntercept`: кнопка фиксации перехвата.

### 3. Ловушки и решения
- **Ловушка**: Сетевой лаг WebSocket ($30-50$ мс) приводит к тому, что нажатие регистрируется, когда цель уже сместилась.
  *Решение*: Вычисление фазового упреждения: нажимать кнопку за 40 мс до момента пересечения траекторий.

### 4. Пошаговый алгоритм
1. Замерить скорость цели $V = \frac{\Delta X}{\Delta t}$.
2. Спрогнозировать время встречи визира и цели $t_{\text{meet}}$.
3. Установить таймер на $t_{\text{meet}} - 40$ мс и отправить `click(BtnIntercept.ScreenCenter)`.

## M16: Rhythm Phase Detector (Ритм-детектор фазовых импульсов)

### 1. Суть механики
Метроном генерирует световые и звуковые импульсы с темпом 120 BPM ($T = 500$ мс). Игрок должен совершить серию из 5 ритмичных кликов в фазе «HIT» (допуск $\pm 60$ мс).

### 2. Маячки URDT
- `M16_RhythmPhaseDetector`: `Urdt2DModuleTarget`.
- `BeatIndicator`: световой маяк (свойство `StateString == "BEAT"` или `NumericValue == 1`).
- `BtnRhythmTap`: кнопка отбивания такта.

### 3. Ловушки и решения
- **Ловушка**: Ожидание появления сигнала приводит к задержке из-за времени реакции.
  *Решение*: Синхронизация по постоянному интервалу: первый клик по сигналу, последующие 4 клика — строго с периодичностью 500 мс.

### 4. Пошаговый алгоритм
1. Зафиксировать первый импульс `BeatIndicator`.
2. Запустить цикл из 5 тактов с шагом ровно 500 мс.
3. На каждом такте отправлять `click(BtnRhythmTap.ScreenCenter)`.
4. Зафиксировать 100% точность ритмического паттерна.
