# Решение типовых проблем и ловушек в 2D-окружении (2D Troubleshooting & Pitfalls)

Данный документ содержит каталог 15 критических проблем и ловушек, выявленных при прохождении 32 механик 2D-полигона, и готовые рецепты их устранения.

---

### 1. Деталь не защелкивается в паз и возвращается на базу
* **Причина**: Использование одношагового драга (`steps: 1`). Unity `EventSystem` не успевает вызвать `IDragHandler`, интерпретируя ввод как клик.
* **Решение**: Всегда передавать `steps: 20` в команду `drag`.

### 2. Промах мимо радиуса примагничивания ($R_{\text{snap}}$)
* **Причина**: Отпускание детали за пределами порога захвата (обычно $80-120$ px).
* **Решение**: Целиться строго в `ScreenCenter` целевого слота `Urdt2DSlotTarget`, а не в его границу.

### 3. Попытка установить мусорную деталь (Дефектная деталь 'X')
* **Причина**: В лотке присутствуют визуально схожие детали с признаком `IsJunk == true`.
* **Решение**: В коде агента всегда фильтровать детали: `items.filter(x => !x.components.Urdt2DDraggableTarget.IsJunk)`.

### 4. Нарушение порядка слоев в послойной сборке (M04)
* **Причина**: Попытка установить верхний слой до установки базовых слоев.
* **Решение**: Сортировать детали по свойству `LayerIndex` (1 $\to$ 2 $\to$ 3 $\to$ 4) и выдерживать паузу 400 мс между слоями.

### 5. Отскок маятника из чаши за счет пружины (M07)
* **Причина**: Завершение драга с ненулевой скоростью движения мыши.
* **Решение**: Ввести обязательную Dwell-паузу (450–500 мс) в точке назначения перед отправкой `pointer_up`.

### 6. Срез углов в узком канале вейпоинтов (M08)
* **Причина**: Попытка прямолинейного перемещения между несоседними точками приводит к касанию стенок канала ($W = 45$ px).
* **Решение**: Трассировка непрерывного кусочно-линейного сплайна через `press_move` строго по массиву всех 5 контрольных точек.

### 7. Выстрел из рогатки в противоположную сторону (M14)
* **Причина**: Драг снаряда в сторону цели.
* **Решение**: Вектор натяжения жгута рогатки направлен СТРОГО В ОБРАТНУЮ СТОРОНУ от цели: $\vec{P}_{\text{pull}} = \vec{P}_{\text{anchor}} - (\vec{P}_{\text{target}} - \vec{P}_{\text{anchor}})$.

### 8. Опоздание при перехвате движущейся цели (M15)
* **Причина**: Сетевая задержка передачи пакета WebSocket ($30-50$ мс).
* **Решение**: Расчет фазового упреждения: инициировать клик за 40 мс до момента пересечения траекторий.

### 9. Клик не срабатывает из-за перекрытия текстом (TextMeshPro)
* **Причина**: У дочернего `TextMeshProUGUI` включен флаг `raycastTarget = true`, блокирующий клик по родительской кнопке.
* **Решение**: Убедиться, что на всех текстах отключен `raycastTarget`, или использовать прямой перехват клика по координатам.

### 10. Дрейф координат из-за изменения разрешения Game View
* **Причина**: Использование закешированных или статически прописанных пиксельных координат.
* **Решение**: Все координаты запрашивать через `query` / `inspect` динамически непосредственно перед выполнением физического действия.

### 11. Потеря следующего уровня из-за отсутствия паузы празднования
* **Причина**: Попытка взаимодействия со сценой во время активного двухсекундного поздравительного оверлея (`VictoryCelebrationRoutine`).
* **Решение**: При достижении `ProgressNormalized == 1.0` выдерживать паузу 2500–2800 мс для корректного перехода к следующему модулю.

### 12. Падение башни из физических блоков (M20)
* **Причина**: Смещение центра тяжести блоков по горизонтальной оси.
* **Решение**: Строгое позиционирование всех блоков по единой оси $X = 640$ и мягкое опускание с паузой затухания 500 мс.

### 13. Брак детали при вырезании контура (M29)
* **Причина**: Контур не был замкнут (последняя точка не соединена с первой).
* **Решение**: Добавлять в конец массива пути первую точку: `path.push(path[0])`.

### 14. Перелив жидкости из-за инерции струи (M31)
* **Причина**: В падающей струе остается объем жидкости, который доливается после отпускания кувшина.
* **Решение**: Завершать налив упреждающе, при объеме $V_{\text{target}} - 15$ мл.

### 15. Конфликт указателей при мультитач-управлении
* **Причина**: Использование одного и того же `pointerId: 0` для одновременного удержания кнопки и перемещения стика.
* **Решение**: Разделять каналы ввода: удержание на `pointerId: 1`, управление движением на `pointerId: 2`.

### 16. Смещение элементов при произвольном разрешении Game View (Resolution-Agnostic)
* **Причина**: Использование статических пиксельных координат или предположение, что Game View обязан работать в 1080p. При произвольном размере окна (4K, Ultrawide, Free Aspect) `CanvasScaler` меняет экранные пиксели.
* **Решение**: Всегда запрашивать свежий `ScreenCenter` через `inspect` / `query` перед физическим действием. URDT рассчитывает координаты через `RectTransformUtility.WorldToScreenPoint` в реальном разрешении. Все относительные жесты вычислять в процентах от текущего вьюпорта.

### 17. Падение CLI в PowerShell при передаче сырого JSON
* **Причина**: Одинарные кавычки в Windows PowerShell срезают внутренние двойные кавычки (`Expected property name or '}' in JSON`).
* **Решение**: Использовать типизированные команды CLI: `node Tools/urdt-cli.js click <testId>`, `drag <from> <to>`, `inspect <testId>` или запускать `node Tools/urdt-cli.js --repl`.

### 18. Отсутствие маячков механики при поиске сразу после старта сцены
* **Причина**: Префабы 2D-механик (M01..M32) не существуют в сцене изначально. На старте активно главное меню.
* **Решение**: Выполнить двухэтапную навигационную цепочку:
  1. Клик `btn_open_2d_suite` ➔ подтвердить `ActiveWindow == "window_2d_suite"`.
  2. Клик `btn_2d_run_sequential` в `CatalogPanel` ➔ хост заспавнит префаб `M01_SnapToSlot`.
  3. Проверить `query { activeOnly: true }` на наличие `Urdt2DModuleTarget` перед началом игры.
