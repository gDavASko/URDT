# Руководство по расстановке 2D-маячков URDT (2D Beacon Instrumentation Guide)

Это официальное руководство для разработчиков и ИИ-агентов по правильному оснащению любых 2D-мини-игр и механик маячками **URDT (Unity Remote Debugging Transport)**.

---

## 1. Архитектура и принципы 2D-маячков

1. **Строгое разделение ответственности (Single Responsibility Principle)**:
   - Вся 2D-экосистема строится на наборе специализированных компонентов, наследующих `UrdtUiTarget`:
     - `Urdt2DModuleTarget`: корень мини-игры, статус прогресса и инструкции.
     - `Urdt2DDraggableTarget`: подвижные предметы, детали, фишки, зонды, инструменты.
     - `Urdt2DSlotTarget`: приемные гнезда, пазы, контейнеры, чаши весов, ячейки.
     - `Urdt2DInteractiveAreaTarget`: интерактивные зоны, сенсорные секторы, ручки настройки.
2. **Нулевое влияние на логику игры (Zero Coupling)**:
   - Игровые скрипты (`SnapSlot`, `SnapDraggableItem`, `BaseMechanic2DModule`) не требуют импортов URDT для своей работы.
   - Маячки подписываются на публичные события или читают публичные свойства через инспекцию в рантайме.

---

## 2. Подробная спецификация компонентов 2D-маячков

### 1. `Urdt2DModuleTarget`
* **Куда вешать**: На корневой GameObject префаба 2D-механики.
* **Назначение**: Предоставляет ИИ-агенту метаданные модуля, локальную инструкцию и текущий прогресс.
* **Поля в Инспекторе / Свойства**:
  - `MechanicId`: Уникальный строковый идентификатор механики (например, `"M01_SnapToSlot"`, `"M14_SlingshotImpulser"`).
  - `MechanicTitle`: Человекочитаемое название (например, `"Snap-to-Slot Puzzle"`).
  - `Instruction`: Инструкция по прохождению для игрока и агента.
  - `IsCompleted`: Булевый флаг победы.
  - `ProgressNormalized`: Нормализованный прогресс от `0.0` до `1.0`.
  - `Score`: Текущие очки или количество собранных предметов.
  - `TargetScore`: Целевое количество для завершения.

### 2. `Urdt2DDraggableTarget`
* **Куда вешать**: На любой перемещаемый объект (с `RectTransform` или `Transform`).
* **Назначение**: Передает агенту точные экранные координаты центра предмета, его статус захвата и привязку.
* **Поля в Инспекторе / Свойства**:
  - `ItemId`: Идентификатор предмета (например, `"square"`, `"weight_200g"`, `"cloth_hat"`).
  - `Category`: Категория для группировки (`"shape"`, `"weight"`, `"clothing"`).
  - `IsJunk`: Флаг бракованной/дефектной детали (`true` означает, что предмет нельзя класть в слоты).
  - `IsSnapped`: Флаг того, что предмет уже занял свое целевое место и заблокирован.
  - `IsDragging`: Находится ли предмет в процессе перетаскивания прямо сейчас.
  - `CurrentSlotId`: ID слота, в котором сейчас закреплен предмет.

### 3. `Urdt2DSlotTarget`
* **Куда вешать**: На приемные гнезда, пазы, ячейки и корзины.
* **Назначение**: Координатная цель для завершения операций `drag`.
* **Поля в Инспекторе / Свойства**:
  - `SlotId`: Уникальный ID слота (например, `"slot_square"`, `"bin_red"`, `"pan_right"`).
  - `AcceptedType`: Тип предмета, который принимает данный слот.
  - `IsOccupied`: Занят ли слот предметом.
  - `CurrentCount`: Текущее количество размещенных предметов.
  - `RequiredCount`: Требуемое количество предметов для закрытия слота.

### 4. `Urdt2DInteractiveAreaTarget`
* **Куда вешать**: На сенсорные панели полос раннера, вращающиеся ручки энкодера, кнопки удержания, вейпоинты.
* **Поля в Инспекторе / Свойства**:
  - `AreaId`: Идентификатор зоны (`"lane_left"`, `"rotary_dial"`, `"hold_terminal"`).
  - `AreaType`: Тип зоны (`"lane"`, `"rotary"`, `"button"`, `"waypoint"`).
  - `NumericValue`: Числовое значение (угол ручки, уровень заполнения, время).
  - `StateString`: Состояние в виде строки (`"idle"`, `"charging"`, `"press_now"`).

## 3. Автоматическая утилита `Urdt2DBeaconUtility`

Для исключения рутинной ручной расстановки сотен маячков в проекте предусмотрен утилитный класс `Urdt2DBeaconUtility`:

```csharp
using KBP.URDT.TestPoligon.Mechanics2D.Core;

// Вызов в момент создания экземпляра механики в сцене:
public void SetupMechanicInstance(BaseMechanic2DModule moduleInstance)
{
    // 1. Создает или обновляет корневой Urdt2DModuleTarget
    // 2. Рекурсивно сканирует дочерние объекты
    // 3. Автоматически вешает Urdt2DDraggableTarget на все предметы
    // 4. Автоматически вешает Urdt2DSlotTarget на все гнезда и лотки
    // 5. Автоматически вешает Urdt2DInteractiveAreaTarget на зоны
    Urdt2DBeaconUtility.InstrumentHierarchy(moduleInstance);

    // Регистрирует всю созданную иерархию в рантайм-сервере URDT
    KBP.URDT.UrdtServerHost.Instance?.RegisterHierarchy(moduleInstance.transform);
}
```

## 4. Гарантии кликабельности и защита от перекрытия (Raycast Sanitization)

При инструментации 2D-механик в uGUI критически важно соблюдать следующие правила:
1. **Неинтерактивные тексты (TMP_Text)**:
   - Все `TextMeshProUGUI` и `Text`, расположенные поверх интерактивных панелей или кнопок, **ОБЯЗАНЫ иметь `raycastTarget = false`**! Иначе клик виртуальной мыши будет перехвачен текстом, а кнопка не нажмется.
2. **Фоновые подложки и декоративные рамки**:
   - `Image` на декоративных фонах и рамках обязан иметь `raycastTarget = false`.
3. **Объекты-приемники `IDropHandler`**:
   - Слот обязан иметь `Image` с `raycastTarget = true` (хотя бы с альфой 0.01f или прозрачным спрайтом), иначе Unity `EventSystem` не сможет отправить событие `OnDrop`.
