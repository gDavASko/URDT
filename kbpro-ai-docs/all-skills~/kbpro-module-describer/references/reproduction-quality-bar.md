# Reproduction Quality Bar — планка для `*_reference.md`

> Источник правды: [HowToDescribeModule.md](../../../../../kbpro-wiki/raw/Architecture/CoreFramework/Guides/HowToDescribeModule.md) (v2.0). Этот файл — практический чек для скилла `kbpro-module-describer`.

## Главный критерий (reproduction test)

Описание готово **только если** другой ИИ-агент, имея на руках **только этот `*_reference.md` + `HowToCreateModule.md`** и НЕ открывая исходники модуля, сможет собрать похожий рабочий модуль под новое ТЗ.

Если по описанию нельзя ответить на вопрос «какие классы создать, что в них, какие Constants/конфиги завести, как связать DI, как запустить» — описание не закончено.

## Обязательные reproduction-секции (помимо обзорных)

1. **3.6 Конфигурация — ПОЛНЫЙ список** полей SO/Inspector: имя, тип, дефолт, влияние. Не выборочно.
2. **3.7 Структура Prefab** — иерархия GameObject → какие компоненты висят; Addressable address/group; SOGameModuleSettings ID.
3. **3.8 Карта инъекций** — таблица `[InjectComponent] поле системы ↔ тип компонента ↔ провайдер ↔ объект-источник`. ВСЕ инъекции. Без неё модуль падает с NRE.
4. **3.9 Порядок lifecycle** — где именно стоит `base.Initialize/Startable/OnComplete/Dispose` (порядок критичен в KBPro).
5. **3bis Контракт интеграции**:
   - Constants: `MODULES.*` (id модуля), `UICOMPONENT.*` (UI окно), звуки, addressable address, прочие флаги.
   - Базовый класс (`AbstractGameModule` / `InRunnerGameModule`).
   - ModuleInput / ModuleOutput / порты сценария (или «нет»).
   - Способ запуска (`IsolatedGameModuleService.Run(id)` / нода сценария / внутри Runner) с фрагментом кода.
6. **7 Adaptation Guide**:
   - Класс задач, для которого образец подходит.
   - Что взять as-is (конкретные классы/паттерны).
   - **Таблица замен** (реальные имена образца → плейсхолдеры нового модуля; где менять).
   - Что добавить под новое ТЗ; пошаговый рецепт со ссылками на этапы `HowToCreateModule.md`; подводные камни образца.

## Дисциплина точности

- Не додумывать: неизвестное → `[НЕИЗВЕСТНО — уточнить]`.
- Только реальные классы/идентификаторы из кода и конфига.
- Код — только ключевые фрагменты (3–20 строк), не целые файлы.
- Антипаттерны модуля — обязательно («Явных нарушений не обнаружено», если нет).

## Перед сохранением
Пройди чеклист «Правило 6» из HowToDescribeModule.md, включая пункт **Reproduction test пройден**. Файл — UTF-8 с BOM, в `ModuleExamples/<категория>/`, со строкой в `README.md`.
