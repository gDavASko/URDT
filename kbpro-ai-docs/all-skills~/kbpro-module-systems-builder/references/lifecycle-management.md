# Управление жизненным циклом (Lifecycle) в LogicSystem

Этот справочник описывает строгие правила инициализации, работы и очистки ресурсов логических систем `LogicSystem`.

---

## 1. Схема жизненного цикла

Жизненный цикл системы полностью контролируется родительским модулем `AbstractGameModule` и состоит из четырех фаз:

```
[Конструктор] → [Inject DI] → Initialize() → Start() → [OnUpdate] → Dispose()
```

---

## 2. Фаза 1: Инициализация (Initialize)

Метод `Initialize()` вызывается фреймворком после завершения всех инъекций зависимостей `[InjectComponent]`.

### Правила:
- Выполняйте подписки на события компонентов (`+=`).
- Устанавливайте начальные значения стейта (счетчики, флаги).
- **Вызов `base.Initialize()` должен быть строго последней строкой!** Это запускает внутреннюю регистрацию и подготовку системы во фреймворке.

```csharp
public override void Initialize()
{
    // 1. Подписки на вью-слой
    _myComponent.OnActionTriggered += OnActionHandle;

    // 2. Базовый вызов — строго ПОСЛЕДНИМ
    base.Initialize();
}
```

---

## 3. Фаза 2: Запуск (Start)

Метод `Start()` вызывается фреймворком в момент, когда весь модуль готов к запуску геймплея (вызывается из `AbstractGameModule.Startable()`).

### Правила:
- **Вызов `base.Start()` должен быть строго первой строкой!**
- Начинайте проигрывание стартовых анимаций (через методы компонентов), запускайте таймеры, открывайте HUD.

```csharp
public override void Start()
{
    // 1. Базовый вызов — строго ПЕРВЫМ
    base.Start();

    // 2. Запуск логики
    _myComponent.PlayStartAnimation();
}
```

---

## 4. Фаза 3: Обновление (OnUpdate)

Логические системы являются чистыми C# классами и не имеют прямого метода `Update()` от Unity. Если системе требуется обновление каждый кадр:

### Правила:
- Наследуйте интерфейс `IUpdatable` (из `KBP.CORE`).
- Реализуйте метод `OnUpdate()`. Фреймворк автоматически подпишет систему на тик общего таймера модуля.

```csharp
using KBP.CORE;

public class MyTimerSystem : LogicSystem, IUpdatable
{
    private float _timeRemaining;

    public void OnUpdate()
    {
        _timeRemaining -= Time.deltaTime;
        if (_timeRemaining <= 0)
        {
            TriggerTimeout();
        }
    }
}
```

---

## 5. Фаза 4: Уничтожение (Dispose)

Метод `Dispose()` вызывается при закрытии модуля. Это самая важная фаза для предотвращения утечек памяти и зависания процессов.

### Правила:
- **Зеркальность подписок**: Все подписки (`+=`), сделанные в `Initialize()`, должны иметь зеркальную отписку (`-=`) в `Dispose()`.
- **Очистка LazySrv**: Вызывайте `.Dispose()` на всех полях `LazySrv<T>`.
- **DOTween**: Если система вручную запускала твины на долгоживущих объектах, убейте их через `tween.Kill()`.
- **Вызов `base.Dispose()` должен быть строго последней строкой!**

```csharp
public override void Dispose()
{
    // 1. Зеркальная отписка от компонентов
    if (_myComponent != null)
    {
        _myComponent.OnActionTriggered -= OnActionHandle;
    }

    // 2. Освобождение сервисов
    _soundSystem.Dispose();

    // 3. Базовый вызов — строго ПОСЛЕДНИМ
    base.Dispose();
}
```
